# 路线图

## 目标

做一套完全自研的云端 Office 内核，能在浏览器和 App 内以 SDK 形式渲染并编辑文档，支持修订（跟踪更改）和内容增删。格式范围是 Word、Excel、PDF，之后是 PPT。

"自研"的边界：文档模型、排版引擎、编辑内核、格式读写由本项目自己实现；zip 解压、XML 解析、字形处理这类基础设施使用现成的库。

## 已定的技术决定

| 决定 | 理由 |
|---|---|
| 内核用 Rust，编译成 WASM 和原生库 | 各端排版结果一致；大文档性能好；同一份内核可在服务端做转 PDF、出缩略图 |
| 依赖只用 MIT、Apache、BSD、Zlib 协议 | 避开 GPL 和 AGPL，保证代码可自由分发和商用 |
| 字体只用开源可商用字体，并做替换表 | 宋体、微软雅黑等字体不可随 SDK 分发 |
| 先做 Word（docx） | 文字排版引擎是 PPT 文本框、Excel 富文本、导出 PDF 的共同基础 |
| 还原度靠语料对比来衡量 | 规范与 Word 的实际行为有出入，只有实测才算数 |

### 字体替换

| 文档中的字体 | 替换为 | 协议 |
|---|---|---|
| 宋体、新宋体 | 思源宋体 | OFL |
| 黑体、微软雅黑、等线 | 思源黑体 | OFL |
| 楷体 | 霞鹜文楷 | OFL |
| 仿宋 | 待选型 | |
| Arial、Times New Roman、Courier New | Liberation Sans、Serif、Mono | OFL |
| Calibri、Cambria | Carlito、Caladea | OFL |

西文的几款替换字体与原字体字符宽度一致，换行位置基本不变。中文替换字体的行高和标点宽度与原字体有差异，影响程度要在原型 2 中实测。

## 原型阶段

用五个小原型回答最关键的问题，再决定正式架构。每个原型的代码都可能重写。

| # | 原型 | 要回答的问题 | 通过标准 | 状态 |
|---|---|---|---|---|
| 1 | 解析 | 文档模型有多复杂 | 对任意 docx 输出每段文字的最终格式 | 已完成 |
| 2 | 排版 | 换行和分页能与 Word 对齐到什么程度 | 纯文字文档的换行位置和页数与 Word 一致 | 未开始 |
| 3 | 编辑 | 自绘界面上的输入体验是否可行 | 光标、选区、中文输入法可用，输入后局部重排 | 未开始 |
| 4 | 写回 | 能否做到无损保存 | 修改一段并带修订标记，Word 打开不报错，其余内容不变 | 未开始 |
| 5 | 嵌入 | 内核在各端的体积和性能 | 在浏览器和 iOS、Android 中运行，记录体积、启动时间、内存 | 未开始 |

### 原型 1 的结果

`oco-docx` 能读取 docx 并计算最终格式，已覆盖：

- 容器：通过部件关系定位主文档、样式、主题、设置，不依赖固定路径；支持 Transitional 和 ISO Strict 两种命名空间；单个部件有大小上限，防解压炸弹。
- 结构：段落、文字块、表格（含嵌套）、制表符、换行和分页符，以及超链接、内容控件等包装元素。
- 修订：插入、删除、移出、移入，带作者和时间。
- 格式继承：文档默认值、段落样式链、字符样式链、直接格式，逐层叠加。
- 主题字体：把 `minorEastAsia` 这类引用解析成具体字体名，按文档语言选择对应文字的字体。

已用两个不同来源的文档验证：一个基于 Word 模板，一个由 LibreOffice 导出。

得到的认识：

1. **格式不能直接读出来，必须算出来。** 一段文字的字体可能来自四层设置加一个主题文件。粗体、斜体等属性在样式之间是"翻转"关系：粗体标题里套用粗体的字符样式，结果是不加粗。
2. **表格样式是最大的一块未覆盖内容。** Word 模板的样式表里有 649 处表格条件格式（首行、隔行、首列等）。表格的真实外观大部分由它决定。
3. **内核自带"未支持清单"。** 每次读取都会统计遇到但未支持的标记。拿它跑一批真实文档，就能按出现频率决定先做什么。

尚未验证的地方：

- 文档默认值中的翻转属性按规范（ECMA-376 第一部分 17.7.3 节）实现，没有与 Word 的实际表现对比过。
- 没有用 Word 直接保存的、内容丰富的真实文档测试过。

尚未支持、原型 2 之前需要补的：页面设置（`w:sectPr`：纸张、页边距）、制表位、编号和项目符号、表格属性和表格样式、图片、域、页眉页脚、脚注。

## 下一步

1. **建语料库和对比工具。** 收集真实文档，用 LibreOffice（之后加上 Word）导出 PDF 作为标准答案，统计"未支持清单"，并为原型 2 准备逐页对比。
2. **原型 2：排版。** 读取页面设置，加载思源宋体，自己做文字测量、断行、分页，输出每行的位置，与标准答案对比换行位置和页数。
3. 根据前两个原型的结果，确定正式的文档模型。原型 4 要求无损写回，因此模型需要保留不认识的内容，而不是像现在这样丢弃。
